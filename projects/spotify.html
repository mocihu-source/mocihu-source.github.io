01 / CONTEXT

Project Background

Music streaming catalogs contain an enormous variety of tracks, making it difficult to discover songs that match a listener's preferences. This project investigates whether nine numerical Spotify audio features—danceability, energy, loudness, speechiness, acousticness, instrumentalness, liveness, valence, and tempo—can support meaningful content-based music recommendations and playlist analysis.

Starting as a machine learning experiment, the project evolved into a Streamlit application that recommends songs based on audio-feature similarity, explains the characteristics of selected songs, and enables users to save recommendations as a Spotify playlist.

02 / GOALS

Project Objectives

The project aimed to develop a music recommendation experience that allows users to select songs, discover related tracks, and understand their listening preferences through interpretable playlist metrics.

A further objective was to turn the analysis into a usable Streamlit application, including the ability to save generated recommendations as a Spotify playlist.

03 / DATA

Data Description

The analysis uses a dataset containing over 81,000 tracks. Nine audio features describe different aspects of each song: danceability, energy, loudness, speechiness, acousticness, instrumentalness, liveness, valence, and tempo.

The dataset was sourced from Kaggle — Spotify Tracks Dataset (Audio Features). The nine audio features were standardized using StandardScaler before similarity calculations. Additional fields—track_name, artists, track_genre, popularity, and track_id—were retained to display recommendations, analyze playlists, and support Spotify integration.

04 / METHOD

Analytical Approach

Feature Preparation

Each track was represented by nine numerical audio features, standardized using StandardScaler to make the features comparable during distance calculations.

Comparing Recommendation Approaches

Two content-based approaches were explored: Nearest Neighbors, which searches for similar songs across the full catalog, and K-Means + Distance, which first groups tracks by audio characteristics and then searches within the selected song's cluster.

Three distance measures—Euclidean, cosine, and Manhattan—were tested. Following comparison and validation using 100 randomly selected songs, Nearest Neighbors with cosine distance was selected for the final Streamlit application.

Smaller feature-space distances indicate greater similarity in the selected audio characteristics; they do not, by themselves, establish that users will prefer the recommendations.

05 / INTERACTIVE EXPERIENCE

Streamlit Application

The analytical workflow was converted into an interactive Streamlit application. Users can select songs from the available catalog, choose the number of recommendations, generate similar-song suggestions, and explore a playlist analysis. Through Spotipy and the Spotify Web API, the application also includes a feature to save recommendations as a Spotify playlist (subject to Spotify authentication).

Playlist Analysis & Music Taste Profile

The application summarizes the selected songs using six interpretable dimensions: mood (valence), energy, genre diversity, popularity, consistency, and tempo (average BPM). Consistency is calculated using pairwise cosine distance between the selected songs' audio features.

These metrics are translated into a short Music Taste Profile, helping users understand their listening preferences without needing to interpret raw feature values.

06 / RESULTS

Project Outcomes

The project transformed a comparison of content-based recommendation methods on 81,000+ tracks into an interactive Streamlit music discovery application.

The final workflow uses Nearest Neighbors with cosine distance, selected after evaluating alternative approaches and distance metrics on 100 sampled songs. Its main deliverables are audio-feature-based recommendations, an interpretable Music Taste Profile, and Spotify playlist creation functionality.

07 / REFLECTION

Limitations & Next Steps

The Streamlit application has been developed but has not yet been publicly deployed. Its recommendation logic measures similarity between audio features, which does not necessarily reflect subjective listener preferences.

Recommendation quality was evaluated based on audio-feature similarity rather than direct user feedback. Future improvements could include user-based evaluation to better assess recommendation relevance and satisfaction.

Future improvements include optimizing caching and data loading for deployment, improving song search and reducing reliance on a large in-memory dataset, configuring Spotify OAuth for public multi-user access, and evaluating recommendation quality beyond feature-space distance. Recommendation stability, catalog coverage, and user feedback are also areas for further investigation.
